// 02 · the shift

Mobile is a different instrument.

The desktop is for sitting with the archive.
The phone is for catching a moment before it gets away.
Four constraints reshape every decision.
01posture
One thumb. Often outdoors.
Primary actions live below the screen midpoint. No nav at the top edge. The capture surface assumes the user isn't looking at the screen carefully.
02time
Open. Capture. Close.
A capture should take under 10 seconds, including putting the phone back. Anything else fails the moment. Browse sessions are short too — checking what got logged today.
03three views, one screen
Sky · Atlas · Roll collapse.
The desktop's three browsing surfaces need to coexist in 390 pixels of width. Each candidate solves this differently — that's the real fork in the road.
04offline
The signal comes and goes.
Captures queue locally and flush silently when the network returns. The UI mentions it once if you ask — never as an error, never as a banner.

// 07 · the note problem

A blank text box is the wrong answer.

Notes are the only capture that asks the user to produce something. By the time a keyboard opens, the moment has passed. Each candidate proposes a different escape from the blank box.
// candidate A
Voice → note.
Hold the record button, talk for ten seconds, release. Whisper transcribes; the transcript becomes the note body. The user reviews the text later, from desktop, if they want. The pipeline already exists.
// the gesturehold record · release · done
// candidate B
Seeded card.
The note sheet opens with location, weather, and now-playing already filled in. A single one-line input takes a fragment — "the light was strange." Tap to commit. The user adds zero context because the app already knew it.
// the gesturepull up · type · swipe down
// candidate C
Fragment chips.
A grid of pre-canonical short prompts — "a smell" · "the light" · "what someone said" · "a feeling" — populates the sheet. Tap one to seed the input; the cursor is already inside, one line waiting. Or skip the chips and type a fragment cold.
// the gesturetap chip · type · swipe down

// 08 · cross-cutting

Same across all three.

Six decisions that hold regardless of which structural candidate wins. Build these first.
01now playing
A quiet pill, not a tile.
Whatever Last.fm reports lives in a single horizontal pill: ♪ · track · artist. It floats near the top of the screen on candidates A and C, and inside the dynamic island on B. It collapses to a single ember dot when nothing is playing.
02palette
Dark mode, always.
The Cosmographic Atlas palette translates 1:1 to mobile. Contrast bumps up by ~10% to handle outdoor reading. Embers stay calibrated. Film grain stays on the surface — at 55% it survives small screens better than expected.
03place names
Reverse-geocoded, always.
No raw lat/lng anywhere in the UI. "37.7596° N" becomes "Mission · 20th & Valencia". The mono coordinate line shows up only in the entry detail view, as marginalia — like the desktop.
04offline state
Queue silently.
No banner, no warning, no orange dot. Captures save locally and sync when the signal returns. A small mono indicator "3 queued" appears only inside the capture surface — never on the home screen.
05search
A sheet, not a screen.
Tap the search affordance — sheet rises from the bottom. Recent queries, places, tags, dates surface first. Same syntax as the desktop's ⌘K: type:audio in:Lisbon during:autumn. Native iOS keyboard.
06live updates
No toast. Ever.
A new entry captured from this device, or arriving from the websocket, doesn't toast. It appears in the appropriate surface with a single ember pulse and then settles. The user sees the change only if they happen to be looking.
